1. No Back-end (server.js): Criar a rota de atualização

No seu servidor Express/Node, você provavelmente já tem rotas para listar (GET) e cadastrar (POST). Agora, adicione uma rota PUT usando a sua função executarQueryNeon:
javascript
app.put('/categorias/:id', async (req, res) => {
  const { id } = req.params;
  const { nome } = req.body; // Ou o nome da coluna da sua tabela

  const sql = 'UPDATE categorias SET nome = $1 WHERE id = $2 RETURNING *';
  const resultado = await executarQueryNeon(sql, [nome, id]);

  if (resultado) {
    res.json(resultado[0]);
  } else {
    res.status(500).json({ erro: 'Erro ao atualizar categoria' });
  }
});

Ainda no app.js, crie a função editarCategoria. A maneira mais rápida de fazer isso funcionar é usando um prompt simples para pedir o novo nome e enviar para o servidor:

async function editarCategoria(id, nomeAtual) {
  const novoNome = prompt("Digite o novo nome da categoria:", nomeAtual);

  // Verifica se o usuário não cancelou ou deixou em branco
  if (novoNome && novoNome.trim() !== "" && novoNome !== nomeAtual) {
    try {
      const resposta = await fetch(`http://localhost:3000/categorias/${id}`, {
        method: 'PUT',
        headers: {
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({ nome: novoNome })
      });

      if (resposta.ok) {
        // Chame aqui a função que você já usa para recarregar a lista na tela
        carregarCategorias(); 
      } else {
        alert("Erro ao editar a categoria.");
      }
    } catch (erro) {
      console.error("Erro na requisição:", erro);
    }
  }
}

async function salvarEdicao(categoria, novaDescricao) {
    if (!novaDescricao.trim()) {
        mostrarMensagem('A descrição não pode ficar vazia.', 'erro')
        return
    }

    try {
        const resposta = await fetch(`/api/categorias/${categoria.id_categoria}`, {
            method: 'PUT',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ descricao: novaDescricao })
        })
        const dados = await resposta.json()

        if (resposta.ok) {
            idEmEdicao = null
            mostrarMensagem(`Categoria atualizada para "${dados.descricao}"!`)
            carregarCategorias()
        } else {
            mostrarMensagem(`Erro: ${dados.erro}`, 'erro')
        }
    } catch (erro) {
        mostrarMensagem(`Erro ao salvar edição: ${erro.message}`, 'erro')
    }
}

oq seria a rota put

Na programação web, uma rota PUT é o caminho (endereço) criado no servidor (server.js) que serve especificamente para atualizar ou editar um dado que já existe no banco de dados.
Para entender facilmente, pense nos verbos (métodos) HTTP como as ações de um sistema:
• GET (Buscar): O site pede a lista de categorias ao servidor (SELECT).
• POST (Criar): O site envia uma categoria nova para ser salva no banco (INSERT).
• PUT (Editar): O site envia um texto novo e o ID de uma categoria que já existe para substituir a antiga (UPDATE).
• DELETE (Apagar): O site pede para remover uma categoria do banco (DELETE).

Como a rota PUT funciona no seu projeto

Quando você clica no botão Salvar na tela, o seu navegador (app.js) manda um aviso para o servidor no endereço /api/categorias/3 (onde 3 é o ID da categoria) usando o método PUT e levando o novo nome dentro do pacote.
No seu server.js, a rota PUT faz três coisas em sequência:
1. Pega o ID na URL: Descobre qual item será alterado (ex: id = 3).
2. Lê o novo texto: Pega a nova descrição enviada pelo app.js (ex: "Eletrônicos").
3. Atualiza o banco Neon: Executa o comando SQL UPDATE categoria SET descricao = $1 WHERE id_categoria = $2 e devolve o item atualizado para a tela.

• Detalhe sobre os IDs: Você vai notar que, mesmo apagando os itens #1 ou #2, o próximo cadastro novo continuará seguindo a numeração (ex: #6, #7). Isso é normal, pois o tipo Serial do PostgreSQL/Neon nunca reutiliza um número que já foi usado antes.

Como guardar um histórico do que foi excluído (Opcional)

Se no futuro você quiser manter os dados no banco mesmo depois de clicar em "Excluir" (técnica chamada de Soft Delete ou exclusão lógica), o procedimento padrão em sistemas reais é:
1. Criar uma coluna de status na tabela: Adicionar uma coluna ativo BOOLEAN DEFAULT TRUE na tabela categoria.
2. Trocar o DELETE por UPDATE: Em vez de apagar a linha no server.js, você apenas muda o status dela para FALSE:sql
UPDATE categoria SET ativo = FALSE WHERE id_categoria = $1
Use o código com cuidado.
3. Filtrar na listagem: Na hora de listar no site (GET), você busca apenas as categorias ativas (SELECT * FROM categoria WHERE ativo = TRUE), enquanto os registros excluídos continuam visíveis para você lá na aba Tables do Neon com o campo ativo = false.
